Charger diagnostics › How to diagnose a charger
{% endblock breadcrumbs %} {% block content %}

A customer says "the charger doesn't work". This page takes you from their message to an answer for them, and to a ticket for the tech team when you can't solve it.

1. Find the charger

On Charger diagnostics, search by the charger's identity, its name or its serial number. Every tenant is searched, so you don't need to know which one the charger is in. An exact identity wins over partial matches.

2. Start a case

Next to the charger, type the support ticket's number (optional) and click Start. The case is saved, with you as its author, so anyone can reopen it from Latest cases.

3. Answer the questions

You're only asked what can change the answer: which connector only if the charger has several, whether it has power only if it's offline or "nothing happens", the badge number only if they used a badge, and so on. If it happened before today, the app looks back 7 days instead of 24 hours. The charger's live state is shown on the right, with what looks wrong.

4. Read the diagnosis

Once the last question is answered you get the likely cause and how confident the app is (low, medium or high), a reply for the customer and a summary for the ticket, each with a Copy button. The case keeps the diagnosis as it was written, even when the charger changes later.

  • Back undoes your last answer; Start the questions over clears them all.
  • Diagnose again with the latest data rewrites the diagnosis from the charger's current state, e.g. after a remote reset.
  • Close the case when you're done. Edit in the admin lets you fix the ticket number or the status.

5. Ask Claude for a second opinion

When it's available, Ask Claude for an assessment sends the whole case to Claude: what the platform knows about the charger, the checks, your answers and the diagnosis. Drivers' emails and the charger's network identifiers are left out, and badge numbers are masked. You get what's going on, the steps support can take, a reply for the customer, and whether the tech team needs to step in. Check it before acting on it: it says whether it agrees with the diagnosis above. Going Back or starting the questions over drops it, since it was about the old answers.

6. Escalate when support can't solve it

Create the Jira ticket files Claude's draft for the tech team, with a link to the case and the summary. It's the main button when Claude says the case needs the tech team, and it can only be done once per case: the case then shows the issue. Without Claude, copy the summary for the ticket into your usual ticket instead.

Trying it out

Locally, python manage.py seed_fake_data creates fake chargers, one per problem the app diagnoses: search SEED. The README lists what each one shows.
